# ADR-001: runtime стога сена (instancing + hot pool)

- **Статус:** принято
- **Дата:** 2026-08-31
- **Платформа:** Unity 6 (6000.3), WebGL
- **Связанные правила агента:** `.cursor/rules/haystack-constitution.mdc`, `.cursor/rules/haystack-runtime.mdc`

## Решение

Стог — это не тысяча GameObject’ов. Это массив данных соломинок, которые рисуются через GPU instancing. Интерактивна поверхность (или запрос по пространственному хешу). Полноценными объектами с физикой становятся только соломинка в руке и несколько недавно брошенных (пул 1–8). Иголка — флаг на одном индексе.

## Контекст

Игрок разгребает несколько тысяч соломинок по одной и ищет иголку. Цель — браузер (Unity WebGL). В проекте уже есть ECM2 и Cinemachine.

Наивная схема «префаб × N» на WebGL ломается по четырём осям сразу: иерархия Transform, PhysX (однопоточный, контакты в куче), draw calls / overdraw, память WASM. При этом геймплей требует одновременной симуляции **одной** соломинки, а не всех.

## Рассмотренные варианты

| Вариант | Суть | Почему не выбран |
|---|---|---|
| GO + Rigidbody на каждую соломинку | Привычный Unity-путь | Не масштабируется на WebGL уже на 1–2k |
| DOTS / Entities Graphics | Data-oriented из коробки | Слабая/болезненная поддержка WebGL, избыточно для N ≈ 10k |
| Jobs + Burst как основа | Параллельный CPU | WebGL фактически один поток; Jobs не должны быть обязательны |
| Только GPU picking | ID в RT, `ReadPixels` | Работает, но синхронный `ReadPixels` на WebGL даёт микрофризы |
| Все соломинки кликабельны с кадра 1 | Рассыпанная куча | Хуже для «стога» и для CPU; оставляем как возможное расширение |

## Выбранный вариант

Три слоя, один владелец (`HaystackSystem` или эквивалент).

```
Visual instances  — все соломинки, DrawMeshInstanced, один mesh / один material
Pick query        — луч vs капсула через spatial hash; только не-Buried
Hot pool          — 1–8 GO: в руке + settling; после остановки — demote в массив
```

Данные соломинки:

```csharp
struct Straw
{
    public Matrix4x4 LocalToWorld;
    public byte Flags;      // Buried, Grabbed, Discarded, IsNeedle
    public ushort Variant;
}
```

Позы покоя кучи **запекаются в редакторе** (один прогон физики → `Matrix4x4[]` в ScriptableObject). В рантайме PhysX не держит стог.

Геймплей по умолчанию — **открытая оболочка** оставшейся кучи: кликабельны соломинки на внешней поверхности (верх **и** бока), не только корона. Внутри стоит `Buried`, клик сквозь сено не проходит. Сняли соломинку — с новооткрытых соседей снимается `Buried`. Персонаж ходит по отдельному объёму кучи (`HayPileVolume`), который сжимается по высоте **и** диаметру вместе с оставшимся сеном. ECM2 не сталкивается с отдельными соломинками.

Управление (шаги 2–3): луч из центра камеры, hover только у одной соломинки в радиусе руки. **ПКМ** — взять подсвеченную (если рука пуста) или бросить удерживаемую. В руке соломинка — kinematic-объект из hot pool; после броска PhysX до остановки, затем запись матрицы обратно.

Иголка не отдельная система: `Flags |= IsNeedle`. Она **сразу** рисуется своим мешем/материалом (один `DrawMesh`, не отдельный GO). Спавн — случайный индекс у **вертикальной оси** объёма (цилиндр / полусфера / пирамида / куб), не на внешней оболочке; seed стабилен. Пока соломинка `Buried`, её нельзя взять — нужно разгрести поверхность. Победа читается с флага при захвате.

Сложность — пресеты (`HaystackPreset`): радиус, высота, число соломинок, seed. Форма выбирается отдельно на `HaystackSystem`. Позы не сериализуются; Play генерирует layout в память.

## Почему этот вариант победил

- Геймплей («по одной соломинке») совпадает с бюджетом «один hot-объект».
- Instancing: 5k соломинок ≈ 5 draw calls при пачке 1023; матрицы ≈ сотни КБ, не десятки МБ на GO.
- Нет N×N контактов PhysX в рантайме.
- Работает на WebGL 2 без compute, Indirect, DOTS и SharedArrayBuffer.
- Открытая поверхность даёт честный «разгребаю кучу с любой стороны» и отсекает клики сквозь сено.

## Последствия

**Делаем**

- Один low-poly меш соломинки (12–24 tris), opaque или hard clip, GPU instancing.
- Пул 4–8 объектов: grab → follow hand → drop → settle → запись матрицы обратно.
- Spatial hash (ячейка ~0.3–0.5 м) для пика. Hover только у одного id. ПКМ: взять / бросить.
- Слои: `HayVisual`, `HayHot`, `HayPileVolume`.
- Профилировать WebGL-билд, не только редактор.

**Не делаем без явного пересмотра ADR**

- Прозрачное сено, MeshCollider на соломинке, OnMouse на инстансах.
- Тень с каждой соломинки, материал на каждую вариацию.
- Compute shaders, `DrawMeshInstancedIndirect`, Entities, обязательные Jobs.
- Коллизия игрока с каждой соломинкой.

**Практический потолок (ориентир)**

| Визуал | Интерактивность | Оценка на WebGL |
|---|---|---|
| 1–2k GO + физика | все | нет |
| 3–8k instanced, оболочка ~150–400 | 1 в руке + до 4 settling | да |
| 10–20k instanced, оболочка | то же | да, если меш крошечный и без прозрачности |

## Порядок внедрения (не перескакивать)

1. Меш + instanced материал + `DrawMeshInstanced` с запечёнными позами.
2. Клик по капсуле через hash, highlight одного id.
3. Пул из 1 GO: grab / follow / drop / freeze обратно в массив.
4. `Buried` по внешней оболочке оставшейся кучи (не этажи сверху вниз) + коллайдер объёма для ECM2.
5. Иголка как флаг: свой меш с кадра 1 + спавн у вертикальной оси объёма.
6. Профиль WebGL: Physics, Scripts, SetPass.

## Когда пересматривать

Переоткрыть ADR, а не «просто написать иначе в чате», если:

- целевая платформа перестала быть WebGL;
- нужен полностью физический рассыпанный ворох в рантайме;
- CPU-пик не справляется и нужен GPU picking;
- URP + подтверждённый Indirect instancing на целевых браузерах даёт измеримый выигрыш;
- N выходит далеко за 20k и появляется отдельный GPU-culling.

При пересмотре обновить этот файл и оба `.cursor/rules/haystack-*.mdc` одним коммитом.
